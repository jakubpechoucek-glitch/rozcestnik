Jak pracuju s Claude Code

Programovat ručně nemusím. Všechny projekty tady vznikly v Claude Code – AI asistentovi, který dostane přístup k repozitáři na GitHubu, sám píše a spouští kód a výsledek nahraje. Já říkám česky, co chci, a kontroluju, jestli to tak opravdu je.

  1. Zadání obyčejnou řečí

    Popíšu, co mě trápí a co má aplikace dělat, třeba „chci místo Excelu s byty web, kde uvidím výnosy a konce nájmů“. Přiložím Excel nebo odkaz, ze kterého se má vycházet.

  2. Nejdřív dokumentace, pak kód

    U větších věcí nechám Clauda nejdřív rozebrat Excel, sepsat zadání, datový model, vzorce a otevřené otázky do složky docs/. Projdu to a rozhodnu sporné body. Teprve pak se staví (viz Byty a Lukas University).

  3. Malé kroky a hned vidět výsledek

    Claude udělá změnu, sám si stránku otevře v prohlížeči, udělá screenshot a pustí testy. Já pak napíšu krátkou zpětnou vazbu: „tohle dej pryč“, „přidej odkaz na Spotify“, „vrať ten nápad zpátky“.

  4. Commit, push a nasazení

    Každý projekt má vlastní repozitář. Claude pracuje ve své větvi, popíše změnu v commitu a po odsouhlasení ji pošle do main. GitHub Pages nebo Render pak web nasadí samy.

  5. Průběh ve vlastním souboru

    Stav projektu, co je hotové a co zbývá, se vede přímo v repozitáři (PROGRESS.md, roadmapa). Další sezení pak naváže tam, kde to minulé skončilo.

Co se mi osvědčilo

  • Říkat proč, ne jen co. Když Claude ví, k čemu to slouží, navrhne lepší řešení, než bych zadal.
  • Kontrolovat výsledek, ne kód. Proklikám web na mobilu i počítači. Když něco nesedí, popíšu to a Claude dohledá příčinu.
  • Osobní data nikdy do repozitáře. Repozitáře jsou veřejné, takže čísla žijí v databázi za přihlášením a ukázky běží na smyšlených datech (?demo).
  • Jednoduchá technologie, dokud stačí. Většina projektů je statická stránka na GitHub Pages. Server přidávám, až když je opravdu potřeba.
  • Claude i uvnitř aplikace. Morning Briefing volá Claude API každé ráno sám a z novinek napíše scénář podcastu.

Jen HTML, CSS a JavaScript bez serveru a bez buildu. Hosting je zdarma, nasazení = push do main. Nejjednodušší cesta, jak dostat nápad na web.

Supabase jako databáze a přihlášení

Postgres v cloudu s přihlášením. Data chrání pravidla přímo v databázi (Row Level Security), takže kód i repozitář můžou být veřejné a data stejně uvidí jen členové rodiny.

Node aplikace na Renderu

Když je potřeba vlastní backend (API, plánované úlohy, SQLite), běží aplikace na Renderu. Na free tarifu server po nečinnosti usne a první načtení trvá asi minutu.

  • Průběh projektu se vede v PROGRESS.md

Tip: s parametrem ?edit se zapne editor souřadnic. Klikneš do půdorysu a vypíšou se pixely pro nový bod, takže body nemusíš měřit ručně.

Plánovač

Ukázka s demo daty Web (přihlášení) Kód a README

Rodinný kalendář volna: kdy má Lukáš prázdniny v ISM, kdy je Matěj volný na UCL, kolik zbývá Janě z 25 dnů dovolené a kdy můžeme vyrazit spolu. O cestách po jihovýchodní Asii hlasují všichni čtyři.

  • Jeden HTML soubor
  • Supabase (6 tabulek, RLS)
  • Společné přihlášení
  • GitHub Pages

Co umí

  • Roční přehled: řádek pro každého, vybarvené dny volna, svátky a řádek „Spolu“; společné volno od 3 dní je v rámečku
  • Rozpracované návrhy v Přehledu: kdo ještě nenavrhl destinaci nebo nehlasoval (Jana, Jakub, Lukáš povinně, Matěj nepovinně), odznak na záložce s počtem úkolů pro přihlášeného
  • Kdo je kde: soukromé a služební cesty kohokoli z rodiny (např. Matěj v Čechách přes reading week), které se nepočítají do společného volna; Janina soukromá cesta čerpá dovolenou
  • Lety u cesty (datum + text, sloupec plan_volno.lety): v kalendáři Přehledu ✈ v daném dni, detail letu v bublině po najetí myší / klepnutí, po kliknutí se bublina připne a číslo letu je odkaz na Flightradar24; panel Kdo je kde ukazuje jen 4 nejbližší cesty
  • Výjimky ze svátků: „škola / práce i přes svátek“ (např. ISM učí 2. a 3. den ASEAN svátků) zruší volno jen konkrétnímu člověku
  • Společná volna: kdy mají volno Lukáš i Jakub a kolik dnů dovolené by si musela vzít Jana
  • Nabídka volných termínů pro celou rodinu (od 3 dní) – návrh cesty se předvyplní jedním kliknutím
  • Návrh cesty = termín; každý k němu navrhne až 3 destinace (státy s vlajkou) a všichni hodnotí všechny destinace 1–5 hvězdičkami. Vybraná destinace potvrdí cestu a Janě rovnou odečte dovolenou
  • Počítadlo Janiny dovolené: nárok, vyčerpáno, naplánováno, zbývá
  • Úpravy volna, nově vyhlášených svátků a nastavení přímo na stránce

Jak je to postavené

  • Tabulky plan_volno, plan_svatky, plan_nastaveni, plan_cesty, plan_destinace, plan_hlasy v Supabase Rozcestníku, chráněné je_clen()
  • Dovolená se počítá v pracovních dnech; víkendy a filipínské svátky se neodečítají. Matějovi se počítá jen volno mimo výuku na UCL
  • Trigger na serveru zapíše hlas vždy za přihlášeného, takže hlasovat za druhého nejde
  • Prázdniny ISM se jednorázově přepsaly z PDF kalendářů 2026/27 a 2027/28, svátky z Nager.Date a z kalendáře ISM, termíny UCL z oficiálního webu
  • Režim ?demo běží bez přihlášení se smyšlenými daty

Tip: nejdřív data, pak obrazovky. Když jsou prázdniny, svátky a pravidla („co je pracovní den“) v databázi, odpovědi typu „kdy můžeme jet a kolik to stojí Janinu dovolenou“ už jsou jen výpočet.

Jídelníček

Ukázka s demo daty Web (přihlášení) Kód a README

Týdenní jídelníček s hlasováním: ve všední dny večeře, když je přes den doma víc lidí, oběd. Jana, Lukáš a Jakub hodnotí návrhy hvězdičkami a vítěz rovnou plní nákupní seznam na den předem.

  • Jeden HTML soubor
  • Supabase (7 tabulek, RLS)
  • Data z Plánovače
  • Společné přihlášení
  • GitHub Pages

Co umí

  • Hlasování na příští týden: u každého dne návrhy jídel, 1–5 ★ od každého, vede nejvyšší součet; odznak s počtem dnů, kde přihlášený ještě nehlasoval
  • Oběd nebo večeře podle toho, kdo je doma: aspoň dva přes den doma = oběd, jinak večeře, jeden doma = nevaří se; porce podle počtu lidí; vše jde u dne přepsat
  • Typy jídel: 🍳 vaření, 🥪 rychlovka (pomazánka), 🧊 z mražáku, 🛵 objednávka – „Objednáme“ jde kdykoli a z nákupu vše zmizí
  • Nákup na zítra přepočtený na porce, podle oddělení v obchodě, s odškrtáváním a vlastními položkami; souhrn na 7 dní; seznam „Mám doma“
  • Měsíc dopředu: 5 týdnů s vítězi a otazníky tam, kde se ještě hlasuje
  • Recepty s hledáním i podle suroviny, přepočet porcí, archiv; vložení receptu z textu (např. ze Samsung Notes)
  • ✨ Automatický návrh 3 jídel na den – přednost mají jídla, která jsme dlouho neměli

Jak je to postavené

  • Tabulky jid_recepty, jid_suroviny, jid_dny, jid_kandidati, jid_hlasy, jid_nakup, jid_doma v Supabase Rozcestníku, chráněné je_clen()
  • Kdo je doma, čte z tabulek Plánovače (plan_volno, plan_svatky) podle stejných pravidel – služební cesta Jany ubere porci, prázdniny Lukáše přidají oběd
  • Trigger na serveru zapíše hlas vždy za přihlášeného
  • Výchozí recepty jsou v recepty-vychozi.json, z něj se generuje SQL i ukázka ?demo

Tip: projekty se dají skládat. Jídelníček nemá vlastní kalendář – kdo je doma, ví z Plánovače, takže se volno zapisuje jen jednou.

Math Practice

Web Kód Návrh a ověřování výsledků

Příprava na assessment z matematiky (IB AA SL, exponenty a logaritmy). 102 příkladů z pěti PDF rozdělených do 7 kol, jedno kolo na den.

  • Vanilla JS
  • KaTeX
  • Vlastní parser výrazů
  • localStorage
  • node testy
  • GitHub Pages

Co umí

  • Další kolo se odemkne, až je to předchozí dokončené. Poslední kolo je zkouška nanečisto podle loňského testu
  • Odpověď se zkontroluje hned: 3 pokusy, nápověda, řešení i s grafem
  • Úlohy, které napoprvé nevyšly, jdou kdykoli procvičit znovu
  • Náčrty grafů a důkazy se dělají na papír a pak se porovnávají s řešením

Jak je to postavené

  • Úlohy jsou data v data/kola.js se zadáním v LaTeXu a typem odpovědi
  • checker.js přečte zápis jako na kalkulačce (2√3, log_3(x-4), 10e) a výraz ověří dosazením, takže projde jakýkoli správný tvar
  • Číselné výsledky se uznají přesně i zaokrouhlené na 3 platné číslice (standard IB)
  • Test porovná výsledky s markscheme. Ukázalo se tak, že tři řešení ve školních slidech byla chybně

Tip: na tabletu je psaní vzorců otravné. Pomohlo ptát se na „kontrolní číslo“ místo celého vzorce (např. jen N v „zapiš jako log N“) a pod políčko dát živý náhled „rozumím tomu jako…“.

  • Jedno přihlášení (e-mail nebo Google) pro všechny chráněné weby
  • Backlog nápadů s přidáváním a odškrtáváním

Jak je to postavené

  • Všechny weby běží na jakubpechoucek-glitch.github.io, sdílí tedy jeden origin a jedno uložené přihlášení
  • Chráněný web načte /rozcestnik/auth.js a zavolá RodinaAuth.vyzadujPrihlaseni()
  • Členství ověřuje databáze (tabulka členů), ne stránka

Tip: veřejný „publishable“ klíč Supabase smí být v kódu. Bezpečnost zajišťují pravidla v databázi, ne utajený klíč.

Nový projekt sem přidáš zkopírováním jednoho bloku <article class="project"> a odkazu v obsahu nahoře.
